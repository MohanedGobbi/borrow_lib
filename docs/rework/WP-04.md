# WP-04: Server-side pagination, filtering and query counts

Model: **Sonnet · high**. Why: the catalogue, member list and loan history grow without limit
(imports allow 5,000 books per file), but `GET /books`, `/users` and `/borrow-records`
return every row, and the frontend filters them in the browser. `LoansPage` downloads every
borrow record ever made to show the current loans.

Done when the new tests pass along with the existing 53, lint, `tsc -b` and both builds
pass, and the demo build behaves the same as Django.

## Backend

### Pagination (`library/pagination.py`)
`StandardPagination(PageNumberPagination)`: `page_size = 25`, `page_size_query_param = "pageSize"`,
`max_page_size = 100`, page param `page`. Response shape (camelCase, like the rest of the API):

```json
{ "count": 412, "page": 2, "pageSize": 25, "results": [ ... ] }
```

Apply it **only** to `GET /api/books`, `GET /api/users` and `GET /api/borrow-records`.
Do not paginate `/borrow-records/mine`, `/reservations*`, `/activity` (already capped),
`/categories`, `/notifications/mine`.

### Filters
Add `django-filter` (`pip install django-filter`, pin the version pip resolves in
`requirements.txt`, add to `INSTALLED_APPS`). Use `FilterSet`s in `library/filters.py`.

- **Books**: `search` (title, author or ISBN, icontains), `category` (name, exact), `author`,
  `isbn`, `available=1` (free copies > 0, using the `ready_count` annotation from
  `with_ready_count`), `ids=1,2,3` (for the cart). Ordering: `title` (default), `-year`, `author`.
- **Borrow records**: `status` accepts one value or a comma list (`status=BORROWED,OVERDUE`),
  `book`, `user`. Ordering: `-requested_at` (default), `due_date`, `pickup_deadline`.
- **Users**: `search` (first name, last name, email, student/staff ID), `role`.

Keep the existing query-parameter names so current callers keep working. Expose ordering as
`ordering=` with only the fields listed.

### Query counts
- `ProfileSerializer.activeLoans` and `hasOverdue` cost 2 queries per user. Annotate them in
  `UserListView` (`Count` with a status filter, `Exists` for overdue) and read the annotation in
  the serializer, falling back to the current query for bare instances. This is the same pattern
  `freeCopies` uses with `ready_count`.
- `BorrowRecordListCreateView` already uses `select_related("user", "user__profile", "book")`; keep it.

### Tests (`library/test_lists.py`)
- Each paginated endpoint returns the shape above. `pageSize` is honoured and capped at 100,
  and `page` beyond the end returns 404 (the DRF default).
- Each filter listed above works, including `status=BORROWED,OVERDUE`, `available=1` (a book
  whose only copy is READY-held is excluded), and `ids`.
- `assertNumQueries`: `GET /api/users` and `GET /api/books` use the same number of queries
  for 3 rows and for 30 rows.
- Update existing tests that index list responses directly (for example
  `test_circulation_rules.py::test_book_api_reports_free_copies` uses `listed[0]`) to read
  `["results"]`. This is the only allowed change to `test_circulation_rules.py`.

## Frontend

- `src/types/index.ts`: `export interface Page<T> { count: number; page: number; pageSize: number; results: T[] }`.
- `src/api/index.ts`: `apiBooks.list`, `apiRecords.list` and `apiUsers.list` return `Page<T>`
  and accept the new params (`page`, `pageSize`, `ordering`, books: `available`, `ids`;
  records: `status` as string or string[]).
- Shared `src/components/Pager.tsx` (named export): previous/next buttons and
  "Page {page} of {pages}" through `t()` with EN/FR/AR keys. Hide it when there is one page.
  Chevrons must mirror in RTL (`rtl:rotate-180` or logical icons).
- Debounce search inputs by 300 ms before they trigger a fetch (a small `useDebounced` hook in
  `src/hooks/`).

Per page:
- **CatalogPage**: search, category, `available` and `page` go to the server, and stay in the
  URL as they are today (`?q=`, `?category=`, `?available=1`, add `?page=`). Reset to page 1
  when a filter changes. The title count comes from `count`. Category counts come from
  `apiCategories.list()` `bookCount`, not from counting the loaded books.
- **LandingPage**: `apiBooks.list({ available: true, pageSize: 6 })`.
- **CartPage**: `apiBooks.list({ ids: cart.bookIds, pageSize: 100 })`, and skip the request when the cart is empty.
- **InventoryPage**: server-side search + pagination (keep its current columns and actions).
- **BookDetailPage** (staff panel): `apiRecords.list({ book, pageSize: 100 }).results`.
- **LoansPage**: `status: ["BORROWED", "OVERDUE"]`, `ordering: "due_date"`, 50 per page with the Pager.
- **ApprovalsPage / PickupsPage**: status filter, `pageSize: 100`. If `count` exceeds the
  results, show "Showing {shown} of {count}" (new i18n key).
- **OverviewPage / StaffLayout**: where only a number is shown, request `pageSize: 1` and use `count`.
- **UsersPage**: server-side search (debounced) + role + Pager.

## Demo backend (`src/api/demo.ts`)
Mirror everything: the same pagination shape and the same 25/100 defaults, the same filters
and ordering, and 404 for a page past the end. Put the paging in one helper (e.g. `paginate(items, ctx)`).
