# WP-02: Fix the Phase 0 circulation bugs

Model: **Sonnet · high**. Done when `backend/library/test_circulation_rules.py` passes (16 tests
fail today, by design) together with the 33 existing tests, and lint plus both frontend builds pass.
Do not edit the tests to make them pass; if one looks wrong, stop and say why.

New term: **free copies** = `available_copies` minus the book's READY records (copies on the hold
shelf). `available_copies` itself still changes only at pickup (−1) and return (+1).

## 1. Jobs crash on PostgreSQL (`services.py`)

`run_hourly_cancellation` and `run_nightly_overdue` iterate a `select_for_update()` queryset
outside a transaction. Fix: collect the candidate ids without a lock, then for each id open
`transaction.atomic()`, re-fetch it with `select_for_update()`, re-check the status (skip if
it changed) and apply the transition. The jobs must stay idempotent.

## 2. A returned copy skips the waiting list (`services.py`)

Add one helper, e.g. `_hand_to_queue(book, now) -> BorrowRecord | None`, used by **both**
`confirm_return` (after stock +1) and `run_hourly_cancellation` (after a cancel):
- Walk active reservations FIFO. Deactivate and skip any whose user's profile is inactive.
- For the first eligible one: deactivate it, create a READY record (`approved_at=now`,
  `pickup_deadline=now + PICKUP_WINDOW`, `requested_at=reserved_at`), log `QUEUE_HANDOFF`,
  notify the user. Do not touch stock.
- Only hand off when the book has a free copy.

## 3. Deactivated members can still sign in and borrow

- `UserActiveView`: set `profile.user.is_active` to the same value as `profile.active`
  and save both. SimpleJWT then rejects login, access tokens and refresh (all checked
  in `rest_framework_simplejwt`, `CHECK_USER_IS_ACTIVE` default on).
- `create_request` and `create_reservation`: raise `BusinessRuleError` if `not user.profile.active`.

## 4. Approving with no free copy (`services.py`, `serializers.py`)

- Add `free_copies(book)` (`available_copies − READY count`, minimum 0).
- `approve`: lock the book row (`select_for_update`) and raise `BusinessRuleError` when
  `free_copies == 0`.
- `create_request`: use free copies instead of `available_copies` for the "join the queue" check.
- `create_reservation`: allow joining when free copies are 0 (not only when stock is 0).
- `BookSerializer`: add read-only `freeCopies`. Avoid N+1 on `GET /api/books` by annotating
  the READY count in `BookListCreateView.get_queryset` (and the detail view).

## 5. Mirror in the demo backend (`src/api/demo.ts`)

The demo must behave the same way:
- `freeCopies` in `sBook()` (around line 258).
- Handoff helper used by `runJobs()` (around line 336) and the `return` branch of
  `recordTransition` (around line 503); skip users with `active === false`.
- `approve` branch: refuse when no free copy. Request (around line 867) and reservation
  (around line 911) checks use free copies.
