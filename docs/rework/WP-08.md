# WP-08: Password reset, email verification, staff invites

Model: **Sonnet · high**. The contract is `backend/library/test_accounts.py`. It fails to import
today, because `StaffInvite` and the new fields don't exist yet. Do not edit it. Done when
all backend tests pass on SQLite and PostgreSQL, `makemigrations --check` and the CI deploy
check are clean, lint, `tsc -b` and both builds pass, and the browser checks below pass.

## Why
- **No password reset exists.** A student who forgets their password is locked out.
- **Email addresses are never verified.** Anyone can register as anyone.
- **Staff accounts are created with one shared `STAFF_INVITE_CODE`.** Anyone who learns it can
  become staff, and it never expires.

## Email (`config/settings.py`, `library/emails.py`)
- `EMAIL_BACKEND`:
  - console backend when `DEBUG`;
  - otherwise SMTP from the env vars `EMAIL_HOST`, `EMAIL_PORT` (587), `EMAIL_HOST_USER`,
    `EMAIL_HOST_PASSWORD` and `EMAIL_USE_TLS` (1);
  - `DEFAULT_FROM_EMAIL` comes from env, default `"LibBorrow <no-reply@localhost>"`.
  - Tests use Django's locmem backend automatically.
- `library/emails.py` holds one function per email: `send_password_reset`, `send_verification` and
  `send_staff_invite`. Each builds a plain-text message in the recipient's language
  (`en` / `fr` / `ar`; for invites, the inviting admin's language). The subject and body are
  kept in a small dict per language in that module.
- Links use `settings.FRONTEND_URL`:
  - `/reset-password?uid=…&token=…`
  - `/verify-email?uid=…&token=…`
  - `/signup?invite=…`
- The body also names `LIBRARY_NAME` and says how long the link is valid.
- Sending failures must not crash the request: log them, and still answer as specced. The
  invite response includes the link, so an admin can copy it if the email bounces.
- `PASSWORD_RESET_TIMEOUT = 3600` (1 hour).

## Models + migration
- `UserProfile.language`: `CharField(max_length=2, choices en/fr/ar, default "en")`.
- `UserProfile.email_verified`: `BooleanField(default=True)`. The default is True so existing
  accounts and fixtures stay verified; self-registration sets it to False explicitly.
- `StaffInvite`:
  - fields: `email`, `role` (STAFF or ADMIN), `token_hash` (sha256 hex, unique), `created_by`
    (FK User, SET_NULL), `created_at`, `expires_at` (now + 7 days), `used_at`, `used_by`
    (FK, SET_NULL) and `revoked_at`;
  - `is_pending` means unused, not revoked and not expired.
- Expose them in the Django admin.

## Endpoints

**Password reset**
- `POST /api/auth/password-reset {email}` (throttle scope `auth_reset`, 5/hour):
  - always answers 202 with no body difference;
  - emails a link only if an **active** user has that email (case-insensitive);
  - the token comes from `default_token_generator`.
- `POST /api/auth/password-reset/confirm {uid, token, password}`:
  - a bad uid or token → 400;
  - `validate_password` errors → 400;
  - on success, set the password, **blacklist every outstanding refresh token of the user**
    (`OutstandingToken` → `BlacklistedToken`), log `PASSWORD_RESET`, and return 204;
  - the token is single-use automatically, because the password hash changes.

**Email verification**
- Registration sets `email_verified=False` and sends the verification email (unless it is
  invite-based, see below).
- The token comes from a `PasswordResetTokenGenerator` subclass with its own `key_salt`, whose
  `_make_hash_value` includes `email_verified`, so a token stops working once it has been used.
- `POST /api/auth/verify-email {uid, token}` is public: 204 on success, 400 on an invalid token.
- `POST /api/auth/verify-email/resend` needs authentication:
  - 202 when the email is sent;
  - 400 if the account is already verified;
  - throttle scope `auth_reset`.
- `ProfileSerializer` exposes `emailVerified` (read-only) and `language` (writable through
  `PATCH /users/me`, and accepted at registration).
- **Borrowing rule:** `create_request` and `create_reservation` raise `BusinessRuleError`
  when the email isn't verified. The message says to check the inbox.

**Staff invites**, all admin-only (`IsAdmin`) unless marked otherwise:
- `GET /api/invites` returns the pending invites as a plain list, not paginated:
  `[{id, email, role, createdAt, expiresAt, createdBy}]`.
- `POST /api/invites {email, role}`:
  - role must be STAFF or ADMIN, otherwise 400;
  - the token is `secrets.token_urlsafe(32)`, and only its sha256 is stored;
  - email the link, log `INVITE_SENT`, and return 201 with the invite **plus `link`**,
    which is returned this once only.
- `DELETE /api/invites/<id>` sets `revoked_at` and returns 204.
- `GET /api/invites/lookup?token=…` is **public**:
  - pending → `{email, role}`;
  - anything else → 404;
  - throttle scope `auth_login`, so tokens can't be brute-forced.
- **Registration** takes `inviteToken` (optional) and drops `staffInviteCode`, which is now
  ignored if sent:
  - The token must be pending, and the invite's email must equal the registration email
    (case-insensitive). Otherwise answer 400 and create nothing.
  - On success, the role comes from the invite, `email_verified=True` (the link proved the
    address), no verification email is sent, the invite is marked used, and the borrow limit
    is 10 as for staff today.
  - Do the invite check and the user creation inside one `transaction.atomic()` with
    `select_for_update` on the invite, so two sign-ups can't use the same token.
- **Remove `STAFF_INVITE_CODE` everywhere:** settings and the production check, the CI env in
  `.github/workflows/ci.yml`, `DEPLOYMENT.md`, `README.md` and `AGENTS.md`. The first admin
  still comes from `createsuperuser`.
- `seed_demo`: every seeded account is verified, and each gets a `language`.

## Frontend
- **New pages**, default exports, routed in `App.tsx`, inside the existing auth layout look:
  - `ForgotPasswordPage` (`/forgot-password`): an email field. It always shows the same
    "If an account exists, we've sent a link" message.
  - `ResetPasswordPage` (`/reset-password`): new password plus confirmation, then a success
    state linking to sign-in. Show an invalid or expired link clearly.
  - `VerifyEmailPage` (`/verify-email`): verifies on load, with success and failure states.
    If signed in, refresh `me` afterwards.
- **LoginPage:** a "Forgot password?" link.
- **SignupPage:**
  - Remove the staff checkbox and invite-code field.
  - With `?invite=TOKEN`, call the lookup, prefill the email as read-only, and show
    "You're joining as staff/admin".
  - Show an invalid invite clearly, and offer to continue as a student.
  - Send `language` (the current UI language) with the registration.
- **Unverified banner:** a slim notice for signed-in members with `emailVerified === false`,
  with a "Resend email" button. Place it in `Layout`, under the header. It uses neutral surface
  colours, not red (see DESIGN.md).
- **Language sync:** when a signed-in user switches language, `PATCH /users/me {language}`
  (fire-and-forget).
- **Staff → Users (admins only):**
  - an "Invite staff" button opening a dialog (email + role select);
  - on success, show the returned link with a copy button;
  - a "Pending invites" panel listing invites with a Revoke action.
- All new text through `t()` in EN, FR and AR. Use logical properties, and put emails and
  links in `dir="ltr"`.
