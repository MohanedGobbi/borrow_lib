Model: **Sonnet · medium**. Builds on the WP-08 email module (`backend/library/emails.py`, which
writes plain text in the member's language and uses `FRONTEND_URL` links) and on F1's
`LibrarySettings.reminder_days_before_due`.

## What gets sent
Today these events appear only in the in-app notification bell. They will also go by email, with
**one email per event per record, never repeated**:

1. **Ready for pickup.** When a READY hold is created, by staff approval or by the queue handoff
   (return, expiry or withdraw). It gives the title, the shelf mark, the pickup deadline and a link
   to My loans. Send it with `transaction.on_commit`, so a rolled-back hold never emails.
2. **Due soon.** A daily job sends it for BORROWED loans whose due date is within
   `reminder_days_before_due` days and that haven't had this reminder yet. It gives the title, the
   due date, and a renewal hint: "You can renew it from My loans" when a renewal is possible, using
   the same checks as F1's `renew`, without raising errors.
   - `reminder_days_before_due = 0` turns this reminder off.
   - **A renewal clears the "sent" mark,** so the new due date gets its own reminder.
3. **Overdue.** Sent once, when the nightly job marks the loan OVERDUE. It says that new requests
   are blocked until the book is returned at the circulation desk.

**Opt-out:**
- new field `UserProfile.email_reminders` (`BooleanField`, default True, with a migration);
- exposed as `emailReminders` on the profile and writable through `PATCH /users/me`;
- it covers all three emails. The in-app notifications always remain.

**Tracking fields on `BorrowRecord`**, with a migration:
- `ready_email_sent_at`;
- `due_reminder_sent_at`;
- `overdue_email_sent_at`.

Set each one only after a successful send. If sending fails, log it and leave the field empty, so
a later run retries the due-soon and overdue emails. A ready email that failed isn't retried.

## Dates and time zone
- Add the setting `LIBRARY_TIME_ZONE` (env, default `"UTC"`) and document it in `DEPLOYMENT.md`.
- Email dates are converted with `timezone.localtime(value, ZoneInfo(settings.LIBRARY_TIME_ZONE))`
  and formatted with `django.utils.formats.date_format(..., "j F Y, H:i")` inside
  `translation.override(member.profile.language)`, so French and Arabic get their own month names.
- Make sure `LANGUAGES` includes en, fr and ar.

## Jobs
- New service function `run_daily_reminders(now=None) -> int`. It is idempotent and locks per
  record, like the other jobs.
- New management command `send_reminders`. Document a daily cron line in `DEPLOYMENT.md` and in
  the README jobs list.
- `RunJobsView` also runs it and returns `remindersSent`. The staff button's description mentions
  reminders.
- The overdue email is sent from `run_nightly_overdue` at the moment of flagging.

## Tests (`test_reminders.py`, with Django's locmem `mail.outbox`)
- Approval sends one ready email in the member's language. A French member gets a French subject
  and a French month name.
- The queue handoff after a return sends the ready email to the next member.
- A rollback sends nothing: force an exception after the hold is created inside `atomic`.
- Due soon:
  - sent once when a loan is within the window;
  - not sent outside the window;
  - not sent again on a second run;
  - sent again after a renewal;
  - not sent when the setting is 0.
- Overdue: one email when flagged, none on the next nightly run.
- Opt-out: no emails, but the notifications are still created.
- A send failure (patch `send_mail` to raise) leaves the field empty, and the next run retries.
- `GET /jobs/run` returns `remindersSent`.

## E2E (`e2e/reminders.spec.ts`)
Staff approves a request, and the student's latest email (demo mailbox or Django file email,
through the existing `latestEmailLink`-style helper) is the ready-for-pickup message with the book
title. Use a book and an account no other spec touches.
