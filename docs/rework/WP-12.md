# WP-12: Replace `useApi` with TanStack Query

Model: **Sonnet · high**. Set the pattern on 2 pages, then convert the rest. Done when the E2E suite
passes on **both** projects, and lint, `tsc -b`, check-i18n, both builds and the backend tests
pass. The E2E suite exists to catch regressions here: run it before you start, so you know it
is green, and again at the end.

## Why
`src/hooks/useApi.ts` is a hand-rolled fetch hook with these problems:
- every mount refetches, and two components needing the same data fetch it twice;
- polling runs on hidden tabs too;
- after a staff action each page calls `refetch()` by hand, so the sidebar counts and the
  other pages stay stale until their next poll.

TanStack Query fixes all four with caching, de-duplication, focus-aware polling and
invalidation.

## Setup
- **Dependency:** `@tanstack/react-query` (v5). Find a working `npm-cli.js` as in earlier WPs,
  because `npm` is broken in Git Bash. No devtools package.
- **`src/main.tsx`:** add a `QueryClientProvider` with one `QueryClient` from
  `src/lib/queryClient.ts`, configured with:
  - `staleTime: 30_000`;
  - `refetchOnWindowFocus: true`;
  - `retry`: never retry an `ApiError` with status 400–499; otherwise retry up to 2 times;
  - mutations: `retry: 0`.
- **`src/api/queryKeys.ts`:** a key factory, so invalidation is exact. For example:

  ```ts
  export const qk = {
    books: { all: ["books"] as const, list: (p: object) => ["books", "list", p] as const, detail: (id: number | string) => ["books", "detail", String(id)] as const, copies: (id: number | string) => ["books", "copies", String(id)] as const },
    records: { all: ["records"] as const, list: (p: object) => ["records", "list", p] as const, mine: ["records", "mine"] as const },
    // reservations, users, categories, stats, analytics, activity, notifications, invites, me
  };
  ```

## Rules for the conversion
- **Reads:** use `useQuery({ queryKey, queryFn })`.
  - Paginated lists use `placeholderData: keepPreviousData`, so the table doesn't flash
    between pages.
  - Where `useApi` used to poll, keep the same interval with `refetchInterval`. TanStack
    pauses polling on hidden tabs by default; keep that.
- **Writes:** use `useMutation`. In `onSuccess`, `invalidateQueries` covers **everything** the
  write changes, not just the current page. For example:
  - approve, reject, pickup and return invalidate `records`, `books` (free copies),
    `reservations`, `stats` and `notifications`;
  - book edit and delete invalidate `books` and `categories`;
  - invite create and revoke invalidate `invites`.

  This replaces the hand-written `refetch()` calls, and `useStaffAction` in `staffContext.ts`
  becomes a thin wrapper around `useMutation`.
- **Errors:** pages read `query.error` and `mutation.error` and show them with
  `errorMessage(t, e)` as today. `useApi`'s stale-response guard isn't needed any more;
  TanStack handles that.
- **Sessions:**
  - On sign-out (`AuthContext.logout` and the `lb:logout` event), call `queryClient.clear()`
    so the next account never sees cached data from the previous one.
  - On sign-in, clear too.
  - `me` stays in `AuthContext`. Don't move auth into the query cache in this WP.
- **Search and filters:** keep the URL state and the 300 ms `useDebounced` as they are. The
  debounced values go into the query key.
- **Delete `src/hooks/useApi.ts`** once nothing imports it.
- **Demo mode** needs nothing special: the query functions still call `src/api/index.ts`.

## Order
1. **Pattern pages:** `CatalogPage` (a paginated public list with URL filters) and
   `ApprovalsPage` (a staff list plus a mutation that must update the sidebar count in
   `StaffLayout` at once, without waiting for a poll).
2. **The rest:** every other `useApi` user. Grep for them.
3. **Delete `useApi.ts`**, run every check, then run the E2E suite twice.
