# WP-13 (+ WP-14): End-to-end tests against both backends

Model: **Sonnet · high**. The suite is written once and runs against **two targets**:
- the in-browser demo API;
- the real Django API.

That covers WP-14: a rule the two backends disagree on fails in one project and not the other.
Done when both Playwright projects pass locally, the CI job is added, and lint, `tsc -b`, both
builds and the backend tests still pass.

Why now: WP-12 (replacing `useApi` with TanStack Query) rewrites how every page loads data.
These tests are its safety net, so they come first.

## Setup
- **Dev dependencies:** `@playwright/test` and `@axe-core/playwright`. Install Chromium only
  (`npx playwright install chromium`, run through node, since npm is broken in Git Bash).
- **Tests live in `e2e/`** (TypeScript), with `playwright.config.ts` at the repo root and the
  `e2e/` folder excluded from the app's tsconfig and lint if they would clash. Add npm scripts
  `e2e` (both projects) and `e2e:demo` (demo project only).
- **Two projects in `playwright.config.ts`**, each with its own `webServer`:
  - `demo`: `vite --mode demo --port 4300 --strictPort`. The state is per browser context
    (localStorage), so every test starts from the seed automatically.
  - `django`: a backend and a frontend.
    - The backend is a small script, `e2e/serve-django.mjs` (or `.py`), that:
      - deletes `backend/e2e.sqlite3`;
      - runs `migrate` and `seed_demo` with `DB_NAME=e2e.sqlite3`;
      - starts `runserver 8100` with `DJANGO_DEBUG=1`, `FRONTEND_URL=http://localhost:4301`,
        `EMAIL_BACKEND=django.core.mail.backends.filebased.EmailBackend` and
        `EMAIL_FILE_PATH=<repo>/e2e/.mail`.
    - The frontend is `vite --port 4301 --strictPort`, with its `/api` and `/media` proxy pointed
      at 8100. Add an env override for the proxy target in `vite.config.ts`, e.g.
      `process.env.API_PROXY_TARGET ?? "http://localhost:8000"`.
  - The Django state is shared across tests, so that project runs with `workers: 1`, and each
    spec uses **different seeded books and accounts** so order doesn't matter. Read
    `backend/library/management/commands/seed_demo.py` (mirrored in `src/api/demo.ts`) for the
    accounts, books and existing records.
- **Settings:** let `EMAIL_BACKEND` and `EMAIL_FILE_PATH` be overridden by env in debug mode
  (today `DEBUG` forces the console backend). Add `e2e/.mail/` and `backend/e2e.sqlite3`
  to `.gitignore`.
- **Fixtures in `e2e/fixtures.ts`:**
  - `signIn(page, email)` uses the normal sign-in form with password `password123`; don't rely
    on the demo's one-click buttons, so both projects share the code.
  - `latestEmailLink(project, pattern)` reads the newest file in `e2e/.mail` for `django`, and
    the `/demo/mailbox` page for `demo`.
  - `expectToast(page, text)`.
- **Selectors:** prefer `getByRole` / `getByLabel` with the **English** UI text. Add a
  `data-testid` only where a role and name can't identify an element (e.g. a row in a staff
  table), and keep those few.

## Specs (one file each)
1. **`circulation.spec.ts`:**
   - a member requests a book that has free copies, and sees it as pending in My requests;
   - staff approves it (Approvals), then confirms the pickup (Pickups). The book page shows
     one fewer copy available;
   - staff confirms the return (Loans). The copy count is back.
2. **`overdue.spec.ts`:** Daniel (who has an overdue loan) tries to request a book and sees the
   overdue toast. Nothing new appears in his requests.
3. **`waiting-list.spec.ts`:** pick a seeded book with no free copies.
   - a member joins its waiting list;
   - staff confirms the return of one of its loans;
   - the member's My requests shows a hold ready for pickup, and their notification bell has
     the "now held for you" message.
4. **`session.spec.ts`:**
   - sign in, reload, and you are still signed in;
   - `localStorage` has no `lb_access` or `lb_refresh`;
   - sign out, reload, and you are signed out.
5. **`password-reset.spec.ts`:** use "Forgot password?" for a seeded member, follow the
   emailed link, set a new password, and sign in with it.
6. **`inventory.spec.ts`:** staff edits a book's shelf location (the change shows on the book
   page), then deletes a book with no loans (it is gone from the catalog search).
7. **`arabic.spec.ts`:**
   - switch to Arabic: `<html dir="rtl" lang="ar">`, and the catalog heading and a book's
     request button are in Arabic;
   - a member with an overdue loan gets the Arabic `overdue_block` message.
8. **`a11y.spec.ts`:** run axe on landing, catalog, book detail, sign-in, My requests (signed
   in) and the staff overview (staff).
   - **Fail only on `critical` violations.**
   - Write all `serious` ones to `e2e/a11y-report.md` (rule, page, count) for WP-24, and commit
     that report.
   - If a critical violation shows up, fix it if the fix is a one-liner; otherwise mark that
     single check `test.fixme` with the reason, and list it in your report.

Run the demo project with the default parallelism. If a test fails on one project but not the
other, that is a real mismatch:
- fix the **demo** to match Django (Django is the source of truth);
- unless Django is clearly wrong, in which case stop and report it instead of changing
  backend rules.

## CI
Add a job `e2e` to `.github/workflows/ci.yml`:
- Node 22 and Python 3.12;
- `npm ci`, then `pip install -r backend/requirements.txt`;
- `npx playwright install --with-deps chromium`;
- `npx playwright test`;
- upload `playwright-report/` as an artifact when the job fails.

## Report
- the specs and how many tests run per project;
- any demo/Django mismatches found and how you resolved them;
- the critical and serious a11y counts;
- the run time of each project.
