# WP-09: Error and notification codes, translated in the UI

Model: **Sonnet · high**. There is no Opus contract file this time; write the tests listed under
"Tests". Done when all backend tests pass, lint, `tsc -b`, both builds and the new i18n check pass,
and the browser checks pass.

## Why
Every error the API returns is an English sentence. The UI shows `e.message` directly, so
French and Arabic users read English toasts ("Borrow limit reached (5)…"). Student
notifications ("Your request for … was approved") are stored as English text too.
`DECISIONS.md` #18 lists this as the main gap in the trilingual promise.
The bulk import already does it right: `importing.py` returns `{"code": "isbn_invalid"}` and the
UI translates `importErr.*`. Apply that pattern everywhere.

## Response shape
Every error response from `/api/*` gets machine-readable fields, and `detail` stays for API clients:

```json
{ "detail": "Borrow limit reached (5). Return a book first.", "code": "borrow_limit", "params": { "limit": 5 } }
```

Validation errors keep DRF's per-field messages and add their codes:

```json
{ "detail": "Invalid input.", "code": "invalid", "fields": { "password": ["…"] }, "fieldCodes": { "password": ["password_too_common"] } }
```

## Backend

### `library/errors.py`
- `class AppError(Exception)` with `status = 400` and `__init__(self, code, message, **params)`.
- `BusinessRuleError(AppError)` (400) and `StateMachineError(AppError)` (409) move here.
  `services.py` re-exports them so `services.BusinessRuleError` keeps working in tests.
- Add `Forbidden(AppError)` with status 403.
- `exception_handler(exc, context)`, set as `REST_FRAMEWORK["EXCEPTION_HANDLER"]`:
  - **`AppError`:** return `{detail, code, params}` with its status.
  - **Any DRF `APIException`:** run DRF's default handler, then add `code`.
    - When `exc.get_codes()` is a string, use it (`not_authenticated`, `authentication_failed`,
      `permission_denied`, `not_found`, `throttled`, `method_not_allowed`, `parse_error`,
      SimpleJWT's `no_active_account` / `token_not_valid`, …).
    - For `Throttled`, add `params: {wait: seconds}`.
    - For a `ValidationError` with a dict body: `code: "invalid"`, `fields` (the messages) and
      `fieldCodes` (from `get_codes()`). Keep DRF's top-level keys too, so existing callers
      reading `data.detail` or `data.password` keep working.
  - **`Http404` and Django's `PermissionDenied`** go through DRF's mapping as today.
- **Delete the `business_errors` decorator.** Services and views now raise; the handler formats.

### Replace every hand-written error
All `Response({"detail": …}, status=4xx)` and `ValidationError({"detail": …})` in `views.py`,
`account_views.py` and `auth_views.py` become `raise <AppError subclass>(code, message, **params)`.
Use these codes, with params in braces:

| Where | Code |
|---|---|
| services: inactive / unverified / overdue | `account_inactive`, `email_unverified`, `overdue_block` |
| services: limit | `borrow_limit {limit}` |
| services: request with no free copy | `no_free_copy` |
| services: duplicate request / queue | `already_requested`, `already_queued` |
| services: reserve while copies are free | `copies_available` |
| services: approve / pickup without a copy | `approve_no_free_copy`, `pickup_no_copy` |
| `_assert_transition` | `invalid_transition {action, status}` |
| members-only request / reserve (403) | `members_only` |
| book total below on-loan; delete with loans | `total_below_on_loan {onLoan}`, `book_on_loan` |
| category delete with books | `category_has_books` |
| receipt for someone else (403) | `forbidden` |
| delete own account / delete admin | `cannot_delete_self`, `cannot_delete_admin` |
| role endpoint | `invalid_role` |
| import: bad body / `ValueError`s | `import_bad_rows`, `import_bad_mode`, `import_too_many_rows {max}` (give `run_import` its own `ImportError_` codes, or map its two messages) |
| registration with a bad invite | `invite_invalid` |
| invite lookup miss (404) | `invite_not_found` |
| inviting an existing account | `account_exists` |
| bad reset/verify link | `link_invalid` |
| resend when verified | `already_verified` |
| refresh/logout without header (403) | `csrf_missing` |
| refresh without cookie / bad token (401) | `no_session`, `session_expired` |

## Frontend
- **`ApiError`** (`src/api/client.ts`) gains `code?: string`, `params?: Record<string, unknown>`
  and `fieldCodes?: Record<string, string[]>`, filled from the response body. A network failure
  becomes `new ApiError(0, …)` with `code: "network"`.
- **`src/lib/errors.ts`:** `errorMessage(t, e, fallbackKey = "toast.failed")`:
  1. `ApiError` with a `code` whose `err.<code>` key exists: return `t(key, params)`.
  2. `ApiError` with `fieldCodes`: return the first known `err.<fieldCode>` (password rules,
     `required`, `invalid` email, `unique`).
  3. A status fallback: 401 `err.not_authenticated`, 403 `err.permission_denied`,
     404 `err.not_found`, 429 `err.throttled`, ≥500 `err.server`, 0 `err.network`.
  4. Otherwise `t(fallbackKey)`.

  This needs a `has(key)` (or an equivalent) exported from the i18n module. Today `t()` returns
  the key itself when it is missing.
- **Replace every `e.message` shown to users** with `errorMessage(t, e)`. That covers the call
  sites in `BookActions`, `BookEditDialog`, `InviteStaffDialog`, `SignupPage`,
  `ResetPasswordPage`, `ImportBooksPage` (both), `InventoryPage`, `OverviewPage`,
  `UserDetailPage`, `UsersPage`, `MailboxPage` and the `useApi` error strings where they are
  rendered. Grep for `.message` in `src/pages` and `src/components` to catch the rest.
- **`CartContext`:** `submitAll()` returns the failed errors themselves, not strings, and
  `CartPage` formats them with `errorMessage`.
- **Dates:** translated params that hold dates (`dueDate`) are formatted with `src/lib/time.ts`
  before they reach `t()`.
- **Notifications** (`Layout.tsx`): render `t("notif.<code>", params)` when the key exists, and
  fall back to `n.message`.
- **i18n:** add `err.*` for every code above plus `err.network`, `err.server`, `err.required`,
  `err.password_too_short`, `err.password_too_common`, `err.password_entirely_numeric`,
  `err.password_too_similar` and `err.unique`; and `notif.*` for each notification code.
  All in EN, FR and AR, in the serious institutional tone of the existing strings.
  Native-speaker review is WP-25, so keep the wording plain.
- **`scripts/check-i18n.mjs`:** fails if the EN, FR and AR dictionaries don't have the same key
  set, and prints what is missing. Add it to the CI frontend job after lint, as
  `node scripts/check-i18n.mjs`.
