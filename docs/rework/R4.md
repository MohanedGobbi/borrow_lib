# R4: Admin-editable site photos

Model: **Sonnet · medium**. The owner asked: "make it so the admin can edit photos". R1 already
reads every photo through `src/lib/siteImages.ts` (`siteImage("hero" | "feature" | "auth")`, with
bundled defaults in `public/images/`). This package makes those slots editable by admins.

**Done when:**
- the new tests pass with the rest;
- `makemigrations --check`, lint, `tsc -b`, check-i18n and both builds pass;
- E2E passes on both projects, including the new spec;
- the browser check passes.

## Backend
- **Model** `SiteImage`, with a migration:
  - `slot` (choices hero / feature / auth, unique);
  - `image_2000`, `image_1200`, `image_640` (`ImageField`, `upload_to="site/"`, random file names);
  - `width` and `height` of the original;
  - `alt_en`, `alt_fr`, `alt_ar` (each up to 200 characters);
  - `credit` (optional, up to 200 characters, e.g. "Photo: Library archives");
  - `updated_at`, `updated_by`.
- **`GET /api/site-images`** (public) returns
  `{hero: {...} | null, feature: ..., auth: ...}`. Each slot has `src` (the 1200 URL),
  `srcset` ("url 640w, url 1200w, url 2000w"), `width`, `height`, `alt` per language, and `credit`.
  A `null` slot means "use the bundled default".
- **`PUT /api/site-images/<slot>`**, admin only, multipart with `file`, `altEn`, `altFr`, `altAr`
  and `credit`:
  - **Upload safety, test each one:**
    - allow only JPEG, PNG or WebP, **verified by Pillow**, not by extension or content type;
    - at most 8 MB;
    - at most 40 megapixels, as a decompression-bomb guard (`Image.MAX_IMAGE_PIXELS` plus an
      explicit check);
    - **strip all metadata** (EXIF, GPS);
    - convert to RGB;
    - minimum 1200 px wide for the hero and feature slots, with error code `image_too_small`.
  - **Re-encode** to WebP at 2000, 1200 and 640 widths, without upscaling past the original.
  - Store the files and **delete the files of the image it replaces**.
  - **Alt text is required** in all three languages, code `alt_required`, because the images
    aren't decorative.
  - Log `SITE_IMAGE_CHANGED`.
- **`DELETE /api/site-images/<slot>`**, admin only, removes the custom image and its files, so the
  slot returns to the bundled default. Log it.
- **Error codes** go through the existing `AppError` handler, with translations in EN, FR and AR.
- **Tests** (`test_site_images.py`, using small images generated in memory with Pillow and
  `MEDIA_ROOT` overridden to a temp dir):
  - a public GET shows null slots by default;
  - an admin upload creates three WebPs with the right widths and no EXIF;
  - replacing an image deletes the old files;
  - staff and members get 403;
  - a non-image, a fake extension, an oversized file, too many pixels and too small an image are
    each rejected with their code;
  - missing alt text is rejected;
  - DELETE resets the slot and removes the files.

## Frontend
- **`src/lib/siteImages.ts`** becomes data-driven: a `useSiteImages()` query (`qk.siteImages`,
  `staleTime` 10 minutes) and a `siteImage(slot, data)` that falls back to the bundled defaults
  and credits when a slot is `null`.
  - `SitePhoto` keeps its `<picture>` with the responsive `srcset`.
  - Phones must still never fetch the 2000 file; keep R1's `sizes` logic.
  - The landing, feature and auth photos keep rendering their defaults while the query loads,
    with no layout shift, using the width and height for the aspect ratio.
- **Footer credits** come from the slots: custom credit text, or the bundled Unsplash credits for
  default slots.
- **Admin Settings page** (`/staff/settings`): a new "Site photos" section in R2's calm style. For
  each slot:
  - a preview at its real aspect ratio, with a note on where it appears ("Landing page, top" and so
    on);
  - "Replace photo" opens a small dialog with a file picker, a local preview, the three alt text
    fields, the credit field and the size requirement in plain words;
  - "Restore default", behind an `AlertDialog`;
  - upload progress, or at least a pending state;
  - errors through `errorMessage`.
  - Invalidate `qk.siteImages` on success.

## Demo (`src/api/demo.ts`)
- Mirror it. The demo has no server, so do the resize in the browser:
  - draw the chosen file to a canvas;
  - export WebP data URLs at 1200 and 640 only (skip 2000, to keep `localStorage` small);
  - reject files over 8 MB or under the minimum width;
  - store the data URLs in demo state.
- If saving would exceed `localStorage` (catch the quota error), answer with a coded error
  `demo_storage_full` that tells the user the demo can't store such a large photo. Bump
  `DEMO_STORAGE_KEY`.

## E2E (`e2e/site-images.spec.ts`)
- The admin replaces the hero photo with a generated test image, written in the test with
  Playwright and a tiny canvas PNG made via `page.evaluate`, or a fixture created in a temp dir.
  The landing hero now uses the new image.
- Restore the default afterwards, because the Django project shares state across specs.
